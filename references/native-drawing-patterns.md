# 原生出图模式

本参考用于“Manifest/JSON → AutoCAD 2020 DWG”、独立 `AcDbDatabase`、跨图克隆、模板资源和无界面回归。它提炼通用边界，不替代项目自己的数据模型、图层标准或实际 SDK 查证。

## 使用本次绘图所需的数据契约

已有 Manifest/JSON 时沿用项目契约，不要求每个普通命令先新建或冻结一套协议。字段按实际消费者需要定义：

- 实体类型、目标图层、单位和坐标语义；需要引用或更新关联时提供可区分的 ID；
- 实际使用的资源角色和定位键；需要追溯或兼容时提供来源修订信息；
- 允许 ARX 修改的字段，例如插入点、端点、属性文字；
- 关联关系，例如 Hatch 对应的边界实体 ID；
- 项目明确要求的输入、底图或资源身份信息，不为每个实体附加整套凭据。

在使用数据的位置检查所需几何、数值、编码、类型与引用是否可用。重复 ID 影响关联、非有限坐标影响绘制等真实错误应明确处理；无关可选字段、未消费对象或旧诊断记录不自动阻断全部输出。未知格式区分读取能力缺口与输入错误，不通过旧绝对路径、跨 DWG handle 或文件名猜业务含义。

## 资源来源和 staging 数据库

推荐以下边界：

1. 从项目配置解析实际需要的资源及逻辑角色。项目已有受控模板身份要求时检查相应资源；不把所有输入 DWG 都变成必须登记 SHA 的受控模板。
2. 生成独立成果文件时，将底图复制到独立任务目录，使用独立 `AcDbDatabase` 作为 staging 目标；仅按输出合同清理该副本的 ModelSpace，保留所需符号表和块定义。导入用户当前 DWG 时，在明确的 owner 和事务中追加，不套用清空 ModelSpace 的步骤。
3. 只读打开资源源库；在明确的目标事务中克隆或生成对象；完成后提交并保存。报告按产品或开发任务需要生成，普通绘图不额外落盘整套审计记录。
4. 失败仅撤回本次未完成且确属本批的临时输出，保留原始资源、可靠成果和必要失败信息。辅助报告失败不自动删除已完成 DWG，具体依赖见[开发效率参考](development-efficiency.md#恢复与交付按实际依赖组织)。

不要把当前工作数据库当成后台目标库，也不要用测试过程直接打开并修改资源原件。

## 跨图克隆：保留原生对象语义

对尺寸、轴号块、属性块、专业符号和图框等源对象，优先使用 `wblockCloneObjects` 与 `AcDbIdMapping`：

- 源 ID 和目标 owner 必须属于各自正确的数据库；克隆后通过 mapping 取得目标 ID，再在目标事务中重新打开。
- 只修改契约允许的字段。原生尺寸保留 DIMSTYLE、文字样式、箭头和所需关联关系；定义点、尺寸线及文字位置按明确合同调整。文字避让不应改变测量值，未约定的偏移与格式沿用原型，不强制覆盖显示文字。
- 移动块参照后，检查其 `ATTRIB` 子实体。先核对所用移动 API 是否已处理属性，仅对未随动且需要移动的属性补充同一变换，避免二次位移，再更新约定的 Tag。
- 对带依赖的块、匿名块、标注样式和对象扩展数据，验证克隆后的依赖是否落在目标库，并用实体级回读确认对象类型和关系。
- 模板选择使用逻辑角色、侧别、序号、资源 ID 和测量值等稳定键；句柄可用于绑定源指纹的对象清单，不能单独作为跨文件唯一主键。

## Hatch 和样式

需要与几何对象保持关系的填充，先把闭合边界多段线写入目标数据库，再用该对象 ID 建立关联边界；完成边界环和图案设置后再评估 Hatch。对象关联边界适用于需要保留实体关系的成果；顶点环按其用途和 SDK 要求处理。修改相关路径时，在开发验证中回读受影响的边界数量、闭合状态和填充类型。

实体尚未入库时，线型、图层和文字样式的 `ObjectId` 必须从目标数据库解析。名称重载可能通过当前工作数据库得到属于另一库的 ID，表现为 `eWrongDatabase`。

目标已有同名记录时，还需检查重复记录处理策略和实际定义。涉及客户已有 DWG、坐标转换、隐藏对象或版本混用时，读取[图纸兼容与交付一致性](drawing-compatibility.md)。

## 开发验证与回读

按[验证与证据](verification.md)选择本次所需层级。对象数量不能证明几何正确；根据改动核对关键实体的类型、坐标、样式、属性、Hatch 边界或关联。真实保存/重开用于验证受影响的持久化行为，不因这份参考要求每次生产绘图都额外启动回读进程。

## 常见失败模式

| 症状 | 常见根因 | 修复方向 |
|---|---|---|
| 尺寸触发 RECOVER 或显示样式漂移 | 强制覆盖原生尺寸属性或继承目标同名依赖 | 克隆经过验证的原型，按合同修改并回读实际依赖与几何 |
| 块圆圈到了目标处，属性文字仍在资源坐标 | 移动 API 未同步处理属性 | 核对属性是否已随动，必要时补变换，并验证 Tag、样式和宿主 INSERT |
| Hatch 出现三角形或半填充 | 边界输入或评估时机不符合对象状态 | 核对闭合边界和评估时机；需提交后重算时，通过 ObjectId 在新有效作用域重新打开 Hatch，再调用 `evaluateHatch()` |
| `eWrongDatabase` 或样式 ID 无效 | 把当前工作数据库的 ID 写入独立库 | 从目标库的图层/线型/样式表解析 ID |
| Core Console 退出码为 0 但命令未执行 | 脚本命令名、加载方式或输出解析错误 | 用已注册命令、探针输出和实际插件哈希证明加载 |
| 数量正确但画面错误 | 断言没有覆盖实际变化 | 按故障定位核对受影响的坐标、样式、属性或关联；视觉问题再验证实际显示 |
| 测试污染资源或复用旧模块 | 直接打开原始 DWG、GUI 仍加载旧 ARX | 只用副本，独立任务目录；重载前卸载旧模块并核对哈希 |

当前参考只覆盖稳定的原生出图模式；MFC、Jig、Reactors、自定义实体、Object Enabler、安装器和 GUI 自动化需要单独的 SDK 查证与宿主验证。
