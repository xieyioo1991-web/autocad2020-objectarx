# 原生出图模式

本参考用于“Manifest/JSON → AutoCAD 2020 DWG”、独立 `AcDbDatabase`、跨图克隆、模板资源和无界面回归。它提炼通用边界，不替代项目自己的数据模型、图层标准或实际 SDK 查证。

## 先固定数据契约

把上游语义放进版本化 Manifest，再让 ARX 只消费契约。每个实体至少应能回答：

- 唯一 ID、实体类型、目标图层、单位和坐标语义；
- 来源模型/修订版本、资源角色、模板资源 ID 或可验证的逻辑键；
- 允许 ARX 修改的字段，例如插入点、端点、属性文字；
- 关联关系，例如 Hatch 对应的边界实体 ID；
- 输入、底图和资源的 SHA-256 或其他可审计来源信息。

加载阶段拒绝重复 ID、未知类型、缺少几何、非法 UTF-8、非有限数值和不符合版本的字段。不要让 ARX 通过文件名、旧绝对路径、跨 DWG handle 或当前图形状态猜业务含义。

## 资源来源和 staging 数据库

推荐以下边界：

1. 资源目录声明相对路径、逻辑角色、隐藏/输出属性和 SHA-256；生产代码只打开通过校验的文件。
2. 将底图复制到独立任务目录，使用独立 `AcDbDatabase` 作为 staging 目标；清理输出副本的 ModelSpace，保留图层、线型、文字样式、标注样式和块定义。
3. 只读打开资源源库；在明确的目标事务中克隆或生成对象；完成后提交、`saveAs`、关闭输入并生成带计数和哈希的报告。
4. 失败时删除本次 staging/输出临时文件，保留原始资源和用户当前图形。

不要把当前工作数据库当成后台目标库，也不要用测试过程直接打开并修改资源原件。

## 跨图克隆：保留原生对象语义

对尺寸、轴号块、属性块、专业符号和图框等源对象，优先使用 `wblockCloneObjects` 与 `AcDbIdMapping`：

- 源 ID 和目标 owner 必须属于各自正确的数据库；克隆后通过 mapping 取得目标 ID，再在目标事务中重新打开。
- 只修改契约允许的字段。原生尺寸的 DIMSTYLE、文字样式、箭头、文字偏移和关联关系应保留；不要为了“看起来可控”重建尺寸、强制覆盖显示文字或重设位置规则。
- 移动块参照后，检查其 `ATTRIB` 子实体。属性是独立数据库对象，必要时对每个属性应用与块参照相同的变换，再更新约定的 Tag。
- 对带依赖的块、匿名块、标注样式和对象扩展数据，验证克隆后的依赖是否落在目标库，并用实体级回读确认对象类型和关系。
- 模板选择使用逻辑角色、侧别、序号、资源 ID 和测量值等稳定键；旧 handle 只能作为诊断线索，不能作为跨文件唯一主键。

## Hatch 和样式

需要与几何对象保持关系的填充，先把闭合边界多段线写入目标数据库，再用该对象 ID 建立关联边界；完成边界环和图案设置后再评估 Hatch。AutoCAD 2020 对象边界通常比手工顶点数组更稳定，但仍要回读边界数量、闭合状态和填充类型。

实体尚未入库时，线型、图层和文字样式的 `ObjectId` 必须从目标数据库解析。名称重载可能通过当前工作数据库得到属于另一库的 ID，表现为 `eWrongDatabase`。

## 证据和回读

按层级分别记录：

| 层级 | 能证明什么 |
|---|---|
| Manifest/资源校验 | 输入结构、来源和资源版本满足契约 |
| 编译链接 | 指定配置生成了指定二进制 |
| Core Console | 指定二进制在指定无 UI 宿主和输入上完成指定命令 |
| DWG 回读/AUDIT | 对象类型、数量、图层、样式、坐标、关联关系和文件完整性满足断言 |
| GUI/业务验收 | 文件选择、交互、视觉效果和业务判定在实际 AutoCAD 中满足范围 |

只统计总对象数不够。至少回读关键实体的 RX class、图层、线型、颜色、样式名、坐标/测量值、块属性宿主关系、Hatch 边界和资源残留情况。输出报告应记录实际加载的 ARX/CRX 哈希、输入哈希、宿主版本、单位、容差、原始日志和覆盖范围。

## 常见失败模式

| 症状 | 常见根因 | 修复方向 |
|---|---|---|
| 尺寸触发 RECOVER 或显示样式漂移 | 重新构造/强制覆盖原生尺寸属性 | 克隆经过验证的原生尺寸，只改定义点并回读 |
| 块圆圈到了目标处，属性文字仍在资源坐标 | 只移动了 `AcDbBlockReference` | 同步变换属性实体，验证 Tag、文字样式和宿主 INSERT |
| Hatch 出现三角形或半填充 | 直接使用顶点数组或过早评估 | 使用闭合对象边界，提交后重新 `evaluateHatch()` |
| `eWrongDatabase` 或样式 ID 无效 | 把当前工作数据库的 ID 写入独立库 | 从目标库的图层/线型/样式表解析 ID |
| Core Console 退出码为 0 但命令未执行 | 脚本命令名、加载方式或输出解析错误 | 用已注册命令、探针输出和实际插件哈希证明加载 |
| 数量正确但画面错误 | 只做数量断言，没有实体级回读 | 增加坐标、样式、属性、关联和视觉/GUI 验证 |
| 测试污染资源或复用旧模块 | 直接打开原始 DWG、GUI 仍加载旧 ARX | 只用副本，独立任务目录；重载前卸载旧模块并核对哈希 |

当前参考只覆盖稳定的原生出图模式；MFC、Jig、Reactors、自定义实体、Object Enabler、安装器和 GUI 自动化需要单独的 SDK 查证与宿主验证。
