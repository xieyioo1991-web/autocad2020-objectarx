# 图纸兼容与交付一致性

用于 AutoCAD 2020 原生插件在已有 DWG 中导入、重复插入、坐标转换和跨电脑交付的排查。以下规则来自两个结构出图项目的代码与验证记录；具体命令、单位、容差和资源角色仍由使用项目定义。

先确认问题对应的实际 ARX、输入文件、目标 DWG 和宿主。以下兼容场景按本次改动选择，不因干净新图通过就认定所有旧图可用，也不要求每次跑全表。

| 症状 | 首先检查 |
| --- | --- |
| 克隆数量正常，字体或尺寸外观变化 | 同名定义、重复记录处理策略、目标对象实际引用的样式 |
| 非零插入点或旋转 UCS 下错位，圆弧方向变化 | 点的坐标系、转换次数、累计块变换、法向与 bulge |
| 看不见的文字参与避让，空文字导致范围异常 | 父块路径、有效图层、属性隐藏标志、范围 API 返回值 |
| 更新插件后结果仍旧，换机时资源指纹不符 | 实际加载路径、输入合同版本、资源清单及文件字节 |

## 同名样式冲突

目标图与资源图可能有同名但不同定义的文字样式、DIMSTYLE 或箭头块。名称相同、克隆计数相同，都不能证明依赖保持一致。

克隆前记录源、目标定义及采用的 `DuplicateRecordCloning` 策略。`kDrcIgnore` 会在发生同名冲突时使用目标已有记录，不能把它当作保留源样式的保证。根据资源用途选择处理方式：

- 需要原型外观时，使用私有定义或 `kDrcMangleName` 隔离依赖，再通过 `AcDbIdMapping` 取得目标对象。必要时显式绑定克隆后的文字样式，并恢复合同指定的成果图层。
- 需要复用目标定义时，先比较项目要求的实际参数。文字样式至少核对字体文件、字体族、大字体、字高、宽度、倾斜及竖排/形文件标志；尺寸还要核对 DIMSTYLE 及文字、箭头等依赖。
- 替换同名定义可能改变客户原有实体。只有任务明确要求更新这些实体时，才采用替换策略，并验证受影响范围。

私有定义或共享块的复用键应包含资源版本和会改变定义的合同字段。缓存损坏时不再复用，能隔离或重建就由程序处理，避免要求用户手动改名或清缓存。句柄可以用于已绑定源指纹的对象清单，跨文件识别仍需资源身份。重命名克隆可能产生 `$0$` 名称；比较原生参数和引用关系，不能仅因名称变化判失败。

相关验证示例：在目标副本中预建同名异字体或异尺寸参数的定义，检查导入、复用或重开后的相关样式与原有实体。缺少字体文件时记录显示条件，不能将字体引用正确写成屏幕显示已通过。

## 坐标转换与重复位移

为输入点、资源局部坐标和输出坐标明确坐标系。二维几何算法可以统一使用 WCS，但应先检查每个 API 的坐标语义。

1. 命令输入点若来自 UCS，进入数据库几何流程前转换到 WCS。转换失败时停止该次操作，不沿用未转换的点。
2. `AcDbPolyline::getPointAt` 的 `AcGePoint3d` 重载返回 WCS 点；二维顶点及 Hatch 环数据要按其 OCS、法向和标高处理。已经是 WCS 的点不要再次应用 OCS 转换。
3. 递归读取嵌套块时累计父子变换；按 SDK 的矩阵约定检查顺序。明确实体是在局部坐标中创建，还是已转换到世界坐标，再决定外层块引用是否承担位移。
4. 在保留顶点顺序、将法向 `-Z` 的 OCS 多段线重建为 `+Z` 输出时，镜像会反转圆弧方向，需要调整 bulge 符号。其他反射或缩放也应核验弧形；不能把“负法向就翻转”用于所有变换路径。
5. 按实际命令的坐标能力处理标高和法向，不能因算法内部使用二维点就把输入 Z 清零或新增非零标高禁令。若已约定只支持特定平面，无法正确转换的相关对象明确报告能力限制；支持其他平面时按投影和输出规则保持其语义。

块参照及其 ATTRIB 按各自坐标语义验证。页面排版使用合同规定的页面原点；正文包围盒和 DWG 缓存范围不能自动替代图框原点。

相关验证示例：按变换链选择旋转 UCS、非零插入点、嵌套块或反向法向，核对受影响的世界坐标、属性对齐点、弧形或尺寸定义点。涉及持久化时检查重开；倾斜平面按项目能力验证。不要把示例中的块层数变成生产限制。

## 隐藏对象与空文字

文字避让、碰撞和轮廓候选应基于本次任务的有效可见性。只检查实体自身图层，无法判断嵌套块里最终参与显示的对象。

- 每层递归都检查实体隐藏状态、图层关闭/冻结状态，并保留祖先块路径。祖先不可见时，不把其后代作为可见障碍。
- 块内 Layer 0 子实体继承父块参照的有效图层；非零图层使用自己的图层，同时受到祖先可见性的限制。图层识别可忽略大小写，输出保留原有名称。
- 属性实例检查自身隐藏标志。非恒定 ATTDEF 不代表实例文字，应从块参照读取实际 ATTRIB，避免把定义与实例重复计入。
- 空或全为空白的 TEXT 不作为文字障碍。保留原实体和数据，只从该次候选计算中排除；MTEXT 格式控制符需要单独解析，不能直接套用普通字符串判断。
- 检查 `getGeomExtents` 的返回状态。在局部障碍查询中，`eNullExtents` 可按无可用范围处理；其他错误仍需按项目错误路径上报。失败范围不能替换成零坐标矩形，也不能吞掉所有异常。

块分解、实例属性和范围计算应保持一致的坐标链。视口冻结、裁剪、动态块等额外显示机制，按任务查证，本规则不代替完整渲染判断。

相关验证示例：按本次可见性改动选择父图层、Layer 0、属性或空文字场景，比较实际候选及避让结果；涉及错误处理时核对其失败范围。几何回读与 GUI 显示验证分别记录。

## 版本混用与跨电脑交付

源码、构建配置、ARX、JSON 合同、底图、资源目录和字段合同存在配套关系。只替换 ARX，不能保证旧 JSON 自动获得新功能，也不能证明旧底图符合新资源合同。

沿用项目发布清单核对实际插件及所需资源，版本混用时定位具体路径、字段和影响。已确认的资源身份或不兼容协议不能靠改哈希放行；历史诊断报告缺失、无关文件变化不自动成为绘图禁令。缺少本模块历史凭据与实际必需资源不兼容是不同问题。

更新资源后，同步资源目录、依赖合同、原型对象清单和相关验证基线。更新会改变请求字段或语义时，用配套前端重新生成 JSON，再确认宿主加载的是对应 ARX。兼容旧 JSON 的范围应明确，已有 DWG 是否需要重生成也要单独说明。

文件字节 SHA-256 与语义比较分别定义。Git 换行转换会改变文本字节；受原始字节指纹约束的资源和合同可用 `.gitattributes` 的 `-text` 保留字节，普通源码和文档保留项目的文本规则。不要对整个仓库一律禁用转换，也不要用归一化结果冒充原始文件哈希。

权威指纹来自与源码版本、验收产物一起固定的发布清单。新增 `-text` 不会恢复已经被转换的文件；先保留差异用于诊断，再从已确认的提交或交付包恢复正确字节，重新导出并校验。未经资源维护和对应验证，不以当前损坏文件重新计算的哈希覆盖发布基线。

从发布清单选择整套已验证文件作为回退锚点，避免只回退 ARX 后继续搭配新合同。清单属于发布追溯信息，不代表宿主运行已经通过。

发布或路径变更的验证示例：检查实际交付目录中的必需文件及资源解析；复制没有改变相关输入时复用已有业务证据，路径变化影响行为时重验对应部分。换机时重新定位 SDK、宿主与所需字体；协议兼容改动再选旧 JSON、新 ARX 或旧底图组合，不把整套发布复演作为普通局部修复前置。
