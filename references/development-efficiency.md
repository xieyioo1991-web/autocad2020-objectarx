# 开发效率与复用实践

用于减少 ObjectARX 开发中的范围扩大、重复验证和运行开销。只选与当前任务有关的做法，不要求额外计划、审批表、公共库或发布系统。基础执行边界见 [SKILL.md](../SKILL.md#开发范围与完成边界)。

## 让检查服务于实际功能

| 容易走偏的决策 | 应采用的处理 |
| --- | --- |
| “可能出错”，所以先增加确认、凭据或拦截 | 找到实际需求或必要技术依赖；没有依据的担忧不成为用户准入条件。可由程序解决的关联、冲突和恢复不转交用户。 |
| 开发时要求严格回读，所以产品每次都完整审查 | 开发验证与默认运行分开。运行检查只覆盖功能必需的有效性、数据保护或用户明确要求，不把无用审查改成警告后继续默认执行。 |
| 旧测试要求拒绝，所以必须保持 | 核对用户要求和行为依据。获准修正的行为同步调整相应预期；保留必要反例，不自动刷新全部基线。 |
| 发现更复杂输入，所以本次必须支持 | 区分现有能力缺陷与新能力。修好共性机制及真实受影响入口，范围外能力另记，不扩成发布前置。 |
| 数量、块深或样本窗口超出旧值，所以输入不合法 | 区分业务约束、ABI/整数/内存限制和临时实现上限。按真实容量补能力，不把任意上限换成另一任意数字。 |
| 局部读取失败、辅助排版失败，所以整套撤回 | 先判断用途、归属和依赖，失败只影响实际依赖部分；可靠主体或上游原图保留，未完成状态如实报告。真正写入/事务失败不能吞掉。 |

这些判断利用当前任务和已有记录完成，不逐项向用户索要批准。需求已明确时直接推进；只有确实缺少会改变目标或重要行为的信息才澄清。猜测与用户确认分别记录。

## 迭代、协作与复用

- 优先复用现有入口、配置、脚本和已确认实现。多个真实调用者需要同一逻辑时再提取小型服务；不因修一个问题自动重构架构或引入框架。
- 一键、分步和独立命令共用读取、关联、布局和绘制服务。入口只处理各自的选择、交互和适配；保留确有依据的类型差异。
- 从真实输入修复机制，避免梁名、句柄、坐标或单图特判。固定夹具数据可作测试定位，不能进入生产准入条件。
- 同一工作区默认一个写入任务；只读审查可并行。需要并行修改时才隔离可能冲突的文件、构建和输出，不能要求每个小任务都建 worktree 或冻结整套工程。
- 复用当前配置、已读上下文和仍有效的构建/测试结果；验证如何选取见[验证与证据](verification.md#按影响选择验证与复用结果)。不为换聊天、写总结或复制报告重新运行业务。
- 工作数据需要跨版本恢复时，集中定义真正影响兼容的版本/策略，维护生产者与消费者的一致性。仅内部优化不自动升级协议或增加确认状态。

## 性能：先消除无用工作，再处理热点

先按用户动作拆分读取、分析、报告装配、绘图、保存和进程启动的时间及实际调用次数。区分调用次数与真正重算次数，父子累计时间不能重复相加；插桩结果用于定位，收益用同条件的正常流程判断。

| 已有经验 | 适用方法与边界 |
| --- | --- |
| 先定位范围再分析 | 按当前图、楼层、构件及用途选择候选，再读取所需字段。无关说明、空表格式区和远处对象不触发全图审查；确实关联的冲突仍处理。 |
| 同次操作只计算一次 | 在同步只读作用域中共享来源、几何、材料和关联结果；依赖变化或跨可编辑交互后重新取得受影响事实。 |
| 缓存算法后仍有大额开销 | 减少整份 JSON/工作记录的重复装配、按值复制、编码和签名；消费者共享不可变结果，需要修改或导出时再建立副本。 |
| 不为判断缓存命中先做完整重活 | 用已知依赖和作用域管理复用；避免把整份大报告复制、序列化后才生成缓存键。哈希相同本身不证明跨操作可安全复用。 |
| 反复启动 CAD、开图和保存 | 同一批次在宿主允许的方式下复用会话；每张图的数据库、结果和错误相互隔离。保留项目要求的最终独立重开，不把失败候选覆盖原生图。 |
| 完整标准图加载成本高 | 从真实标准原生派生所需样式及依赖的轻量模板；保留源文件，源/字体/派生规则变化或缓存损坏时重建。 |
| 相同依赖反复编译或加载 | 复用输入相同的构建结果和已加载只读资源；普通文档变动不使无关二进制自动失效。 |
| 为落选候选提前做昂贵工作 | 先按实际业务条件筛选，复用背景几何和查询准备；完整写入数据、诊断大树按实际消费需要构造，必要诊断不丢失。 |

短生命周期分析上下文应明确数据库、选集、单位、参数、来源和资源依赖。句柄或对象数量不能单独证明内容未变；调用者不能污染共享结果；异常不留下成功缓存。新命令、恢复或编辑后重新判断依赖，现有最终提交检查不因缓存而失效。预览只有产品实际需要时才保留及管理失效，不新增用户预览确认门槛。

原生数据库、Region、尺寸和图形写入遵守宿主线程与对象生命周期。只有独立值上的纯计算才考虑后台处理；没有热点证据时不优先并行化 CAD 写入。

性能对照保持输入、功能、准备状态和计时范围一致，说明是否包含启动、保存、人工等待及开发核验。按波动和问题选取足够样本，不规定所有修改必跑固定次数。局部变快、调用减少或插桩数据不能代替端到端收益；内存峰值与累计处理字节分开报告。几何、样式和必要失败处理保持，删除越界审查须说明需求依据，不能用提速掩盖漏做功能。

## 恢复与交付按实际依赖组织

数据库事务和文件系统有不同边界。只有业务上不可分割的成果及必需依赖才作为整体提交；独立楼层、可选报告或后处理失败不应扣住已完成原图。辅助阶段用可恢复的独立边界，返回具体未完成部分；真正主体/数据库错误按实际影响回滚。

样式重名、缓存损坏和重复生成，优先私有隔离、重建与按归属更新。不能只按图层删除或自动收养用户对象；用户手改需要保留和定位。对象所有权与事务做法见[数据库生命周期](database-lifecycle.md)。

交付复用项目现有入口，提供本次所需的插件、资源和成果，标明验证范围。用户使用会修改的独立副本，避免回写开发基线；只保护实际依赖的文件，不套用别项目的多级目录、四段版本、额外 Ready 标志或全量文件审计。

文件失败处理仅撤回本批拥有的未完成输出，保留已有成果及定位失败所需资料。版本、锚点、备份和清理按项目当前授权管理；普通修复不自动复制完整工程，不因本技能建立新锚点、清理历史或同步技能副本。

## 规则和资料维护

安装路径集中在配置，运行资源相对实际模块定位。每项现行要求有明确维护入口，其他资料引用，不逐版复制测试数量和结论。旧记录保留历史时期与纠正说明，不能继续作为当前指令。项目规则与用户最新要求冲突时处理具体冲突，不默认选择最严格解释。

技能只沉淀方法和适用条件，业务数值、输入能力、运行门槛、交付政策及实时项目进度留在项目。读取只读参考项目不授权修改、同步、提交或推送；技能仓库、安装副本和项目副本分别遵守用户指定范围。
