# 构建与加载

## 版本核对

| 项目 | AutoCAD 2020 基线 | 查证方式 |
|---|---|---|
| 宿主 | Windows x64，R23.1 | `acad.exe` / `accoreconsole.exe` 文件版本及本次启动的完整路径 |
| SDK | ObjectARX 2020，头文件 release 23.1 | `inc/id.h` 与工程实际 include/lib 路径 |
| 编译器 | VS2017 / v141 家族 | 项目声明、MSBuild 路径、实际工具目录及 `cl.exe` 文件版本 |
| CRT | DLL CRT，参考 `/MD` | `inc/rxsdk_common.props`、有效构建配置；不能将 `/MDd` 插件成功编译视为可加载 |
| 字符集 | 采用现有 Unicode 配置 | 项目设置、SDK 字符类型；不要批量改成窄字符 |
| 语言级别 | 使用已确认支持的级别 | 本机项目用 C++17 不等于支持全部 C++17 特性；v141 不能套 C++20 concepts |
| 库 | 2020 SDK 对应 23 系列及模块依赖 | `dbx.props`、`arx.props` 和最终链接输入 |

[官方 2020 Release Notes](https://help.autodesk.com/cloudhelp/2020/ENU/OARX-Readme/files/GUID-4DA730AB-7A47-4663-838B-21E71438D6C8.htm) 的编译器段落指定 VS2017，并写有 15.7.5 及以前的限制。不要把同一 v141 家族下所有补丁一概称为官方支持。

首版制作环境曾记录 VS2017 Build Tools 15.9、工具目录 `14.16.27023`、`cl.exe` 产品版本 `14.16.27054.0`、Windows SDK `10.0.19041.0`、C++17 Release/x64 `/MD`，Core Console `23.1.47.0.0`；探针记录 `_MSC_VER=1916`。这些是有限的本机历史事实，不是所有用户必须安装的精确组合。保留差异说明，在目标机器再核验。不要为追求配置一致而自行升级或卸载工具链。

## 检查工程

1. 找出实际构建的 Configuration/Platform。不要把未激活的 Win32/Debug 段误报为当前配置，也不要忽略它对其他目标的影响。
2. 区分 XML 字面声明、继承的属性表、条件和最终编译/链接命令。只读检查器不运行 MSBuild，也不解析导入；它不能证明最终有效设置。
3. 核对 x64、SDK include/lib、CRT、语言、预处理宏、链接库、模块定义/导出和输出扩展名。检查混用新 SDK、旧库、x86 库、CLR 设置和调试 CRT。
4. 若确需构建，先确认源和输出均在允许工作区，审查构建事件与导入脚本的写入位置。读取受保护源项目时不要在其目录执行构建、清理、Git 写操作或会写日志的脚本。
5. 保留构建命令、配置、源版本/清单、产物路径、哈希和结果。失败时从首个实质错误定位，避免一并改动 SDK、编译器和业务代码。

通用 C++ 的 RAII、const、明确接口仍有价值。现代语法示例需要按 v141 能力裁剪；测试框架版本和工具参数也需兼容。纯逻辑可在独立测试目标测试，但该目标通过不能代替宿主插件验证。

## 按宿主检查模块

`dbx.props` 列出数据库/几何相关库；`arx.props` 在此基础上增加 `accore`、`acad`、`acui23`、`adui23` 等依赖。读取当前 SDK 的实际属性表和最终导入，不能只看文件扩展名判定依赖。

- AutoCAD GUI：核对 ARX 入口/导出、注册与卸载、受信任加载位置和实际 APPLOAD 结果。GUI 命令、对话框、菜单及交互需 GUI 测试。
- Core Console：只测试其支持的接口和依赖；MFC、UI 或交互输入的行为不能从无界面测试推断。
- 首版制作项目曾把**无 UI 依赖的探针副本**从 `.arx` 复制为 `.crx` 并在 Core Console 运行。这是特定二进制的历史经验。改扩展名不会修复 DLL 依赖、导出、ABI 或宿主 API 不兼容。

## 加载失败的排查顺序

1. 保存完整宿主版本、启动方式、实际插件路径/哈希和加载错误；核对加载的是否刚构建的文件。
2. 检查 PE x64、2020 SDK/库、CRT 和缺少的依赖。检查器只读 PE 机器类型，不代替 `dumpbin /dependents`、导出检查或实际加载。
3. 检查 ARX/CRX 模块设计、入口与命令注册，以及 GUI/Core Console 差异。
4. 对可信文件按项目部署方式核对加载路径和安全策略；不把全局关闭安全设置当作默认修复。
5. 使用独立目录中的插件与 DWG 副本复现；不要覆盖正在使用的模块，也不要结束用户的 AutoCAD。只管理本次创建、已记录 PID 的独立测试进程。

每一步只根据证据缩小原因。构建成功、能找到文件、哈希相符都不是“已加载”的证据。
