# 验证与证据

## 分层结论

| 层级 | 可声明的内容 | 不能由此推导 |
|---|---|---|
| 文件/配置检查 | 某文件存在，某属性有字面声明，某哈希相同 | 有效 MSBuild 配置、编译/运行通过 |
| 技能与检查器验证 | 文档结构有效、检查器按用例输出且不改输入 | ObjectARX 工程或业务通过 |
| 编译链接 | 指定配置成功生成该产物 | 插件能加载、命令或业务正确 |
| Core Console | 指定二进制在该宿主/输入上完成指定检查 | GUI 交互、MFC 或所有 AutoCAD 命令可用 |
| AutoCAD GUI | 实际执行的加载/交互/命令通过 | 未运行的业务场景和边界均正确 |
| 业务差分/验收 | 指定基线、样本、判定标准下通过 | 其他样本或整个迁移已完成 |

历史记录可以支持调查和制定下一步，但应写“已有记录显示”，不要写成本轮刚执行。未做的层级写“未执行”，未知字段保持未知。

## 每次运行应记录

- 时间、工作区、测试运行目录、执行命令与退出状态。
- 宿主完整路径、版本、GUI/Core Console 类型；工具链与 SDK 来源、配置和平台。
- 源码版本或文件清单、构建记录、被实际加载的插件 SHA256；副本与原产物的对应关系。
- DWG 测试副本、来源哈希及测试前后对受保护源文件的完整性检查。
- 覆盖范围、断言数量、比较对象、精确/容差判定方式、容差与单位、通过/失败/未知结果、原始日志。

不要为了凑字段编造值；没有源码与产物对应记录时明确该缺口。哈希相同仅说明读取时字节相同，不证明源码来源或现在能运行。

## 使用只读检查器

`../scripts/Inspect-Arx2020.ps1` 接收显式路径：`Workspace` 必需；`ProjectFile`、`SdkRoot`、`BuildToolsRoot`、`AutoCadRoot`、`BinaryPath`、`EvidencePaths` 可选。默认 Release/x64。多个证据路径在 PowerShell 中用数组传入。

脚本输出 JSON，字段含 `Project/Sdk/Toolchain/Host/Binary/Evidence/Findings`：

- `Assessment=InspectionOnly`、`CadExecuted=false` 始终表明这次只检查文件。
- 输入状态为 `Unspecified`、`Missing`、`Read` 或 `Unreadable`；`Read` 表示已读取，不是兼容性验收。
- 工程记录字面声明及祖先条件。仅计算简单单引号字符串相等/不等和 Configuration/Platform 替换；复杂条件标 `Applies=null`。不执行导入、宏表达式、构建事件或目标，`Evaluated=false`。
- SDK 读取 `inc/id.h` 和少量必需文件；工具链/宿主读取文件存在性及产品版本。PE 仅读取机器类型和哈希，不检查完整依赖、CLR 头、导出或 SDK 真实性。
- 证据 JSON 完整保留在 `Record`，深度上限 50；较深或未知格式应直接阅读源日志，不只依赖该工具。
- 原生哈希识别 `NativeSHA256/ArxSHA256/PluginSHA256/PluginHash`，及 `Native` 节点下的 `CopiedPluginSHA256`；排除 `Oracle` 子树。仅支持这些已知字段，不假装理解任意日志格式。
- `BinaryHashes[].Match` 为 true/false/null。没有当前插件、不可读或哈希无效时无法比较；没有识别到哈希也不意味着旧记录匹配。
- 不自动合并多个 `Passed`，不改写精确比较失败与容差比较成功，不推断“产品完成”。退出码 0 只说明检查完成；空 `Findings` 也不是整体通过。

脚本本身不写文件；保存 JSON 的调用方必须核对输出目录位于允许工作区。它不会遍历整台电脑寻找安装，不下载、不构建、不启动宿主、不改注册表。输入不存在或报告未知时，补充证据或人工核对，不擅自安装或升级软件。

## 解释冲突的例子

1. 环境探针 `Passed=true`，只测 64 位、编译器值、建库和几何距离：报告“历史环境探针通过”，业务和 GUI 仍需各自证据。
2. 日志 `NativeSHA256=A`，当前插件 `SHA256=B`：保留旧版本通过记录，说明当前产物尚无这条对应测试。
3. `ExactSignatureEqual=false`，限定生成图层 `NumericToleranceEqual=true`：同时报告精确比较失败和该范围容差通过，保留原总状态、阈值和单位。不要借容差结果将 `Passed=false` 改为 true，也不要把一次容差作为所有项目默认值。
4. SDK 样例有 Win32 配置，但目标是 2020：样例证明可查用法；2020 的目标架构仍须 x64。

## 按影响选择验证与复用结果

优先使用项目已有构建和验证入口。先确定改动影响的行为，避免每次局部调整都跑全部宿主；最终交付仍满足该项目要求的完整检查。

| 改动 | 验证方向 |
| --- | --- |
| 文档、链接或说明 | 内容、引用与差异检查；不启动 CAD 或重建插件。 |
| 业务算法或公共 C++ | 项目要求的目标构建、相关原生断言和受影响入口；公共逻辑扩大关联范围。 |
| 几何、克隆、事务或关联数据 | 增加真实 DWG 副本上的生产流程、保存重开回读、取消/异常回滚及相关兼容反例。 |
| 样式、字体、底图或合同 | 核对真实资源和依赖指纹，验证实际实体定义、坐标和显示字段；不只统计对象。 |
| 构建、测试运行器或发布工具 | 验证相应身份检查、失败路径与证据隔离；改变正式业务门禁时按项目要求扩大验证。 |
| 正式发布 | 对最终候选执行项目规定的完整回归，核对实际交付树与已验证产物相同。 |

复用有效结果前，确认源码、构建配置/工具链、资源、规则合同、夹具、测试程序/脚本及实际二进制均与原证据对应。只有 ARX 哈希相同，不能证明变化后的测试合同或资源已经验证。输入变化后使受影响证据失效，失败修正后重跑相关检查；正式发布是否须重新完整回归以项目门禁为准。无新变化或未决问题，不因另一个聊天、改写报告或增加总结而重复运行。

局部结果与完整结果分开保存并明确范围，局部通过不更新正式发布成功指针。测试调用生产实现，预期来自独立量测、已确认合同或可信基线；不要让被测算法同时计算自己的预期，也不要通过自动刷新预期、放宽容差或手修成果规避失败。

按影响选择旋转 UCS、平移、镜像、比例变化、屏外选择、保存重开、重复命令、跨图复制、取消及晚期失败场景。全字段保留的范围和允许变化字段单独定义；数量相同不代表几何、样式、来源与关联相同。

## Core Console 完成证据与故障归属

退出码为零不单独证明 SCR 完整执行，业务 JSON 断言通过也不证明宿主正常退出。实际宿主运行器按以下信息共同判定，历史报告缺项时保留缺口，不补写成已执行：

- 记录实际启动 PID、时间、宿主路径、退出码、加载模块路径与 SHA。运行目录及 TEMP/TMP 独立，环境和临时共享设置在结束时恢复。
- 每轮生成唯一完成标记。脚本末尾同时写完成文件和独立输出行，检查标记属于本轮；命令回显中含有标记不等于实际执行。结束后等输出读取器刷新再判定。
- 检查非零/缺失退出码、致命错误输出和运行目录中的新转储。系统事件或其他目录的转储按 PID、时间、模块等证据核对归属，不把同时间段所有 accoreconsole 异常归为本工程。
- 按实际依赖决定宿主能否并行。会修改相同 AutoCAD 配置/受信任路径的测试需要共享锁或独立配置；项目构建锁不等于跨项目宿主配置锁。独立文件夹本身不能隔离持久化用户配置。
- 超时只处理本轮记录的测试 PID，不结束其他 CAD。保留失败原始日志，不通过关闭错误报告或吞掉退出码冒充成功。

遇到读取/XData 操作后的堆损坏，先用最小 SCR 和不加载插件的控制组区分产品错误与测试工具错误。案例中 R23.1 Core Console 在隐式回显长 entget/XData 列表时触发过崩溃；可在完整 AutoLISP 表达式外包 `(progn ... (princ))` 保留显式诊断并抑制返回值回显。此方法只针对已复现的输出问题，不是所有堆损坏的通用修复。

混合 Lisp/SCR 脚本必须区分完整表达式、字符串转义、注释、原生 CAD 命令与空输入，不能把整份脚本盲目包进 PROGN。脚本编码按目标宿主实际读取方式验证，含中文路径时检查能否无损表示，不假设 UTF-8 一定可读。宿主测试与测试运行器自身的反例检查分开记录。

## 安排实际测试

先读项目边界与测试脚本，确认所有输出、临时目录、插件和 DWG 副本均符合允许路径。已有脚本即使曾通过，也可能仍写 `C:\Temp` 或源目录；审查并在允许范围制作合适的新测试流程后再运行。

一次测试使用独立运行目录，记录插件与输入哈希。只管理本次启动的已知 PID；超时不结束用户会话。必要的失败日志留在工作区，不覆盖历史记录。针对实际改动选择验证层级，不为文档或只读检查任务自动启动 CAD。
