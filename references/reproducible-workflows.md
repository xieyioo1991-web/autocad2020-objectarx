# 可复现工作流

本参考保留能定位生产实现、输入、测试入口和历史结果的案例方法；不是通用执行器或项目进度表。2026-11-02 复盘已修正将旧拒绝策略、阶段状态和测试条件外推为开发要求的表述。

先选中当前问题对应的一项，再读取案例文件；无需通读全部来源。项目路径均相对于表中案例根目录，属于追溯索引，不是技能安装依赖。实际运行前核对项目现行 AGENTS、输入身份、脚本参数与受影响范围。

## 1. 有限几何：等价输入能识别，真实缺口不能补造

适用：同一形状换成拆段 LINE、直边 PLINE、反向遍历或冗余顶点后失效；或者算法把缺口、错位、回走误认为连续材料。

操作要点：

- 区分闭合材料环与开放路径。只在识别/证明视图去掉真正冗余的直边点；开放路径保留实际首尾，不借归一化补闭口，不改写来源实体。
- 对需要有限支撑的区间，用实际共线线段的区间并集证明完整覆盖。相接拆段可共同证明；缺段、错位或仅无限延长线相交不能证明。
- 多段合并后，重新对原有限线段核验最终范围。逐对近似共线不是可无限传递的等价关系。
- HATCH 的面积一致不足以证明边界一致或无自交；环表示、循环起点、方向与真自交分别检查。只在明确的比较副本规范等价表示，业务合同仍按项目要求严格比较。

复现：从同一真实输入构造合同允许的拆段、冗余点、反向/循环起点变体；另做缺段、部分闭口、错位、非零面积真自交反例。正例比较真实边界及下游配筋/标注，反例检查诊断与源数据未变。容差与支持的曲线类型从项目合同取值，不复制案例数值。

案例 `01autocad-structure-detail`：

- 实现：`src/FiniteGeometry.h` 的 `OpenCorners/Corners/Covered/Runs`，及 `src/TerminalBoundary.cpp`。
- 入口：`Test-Local.ps1` 中按影响选择 `Native`、`MicroGeometry`、`SlabTrim`、`TerminalBoundary`、`Terminal24`；合法参数以当前脚本为准，不要求每次全跑。
- 历史证据：`docs/1.0.2.29交付验证.md` 第 1、3、4、6 项及故障注入引用。该次 HATCH 生命周期覆盖直边材料，不推广为任意曲线材料支持。

## 2. 生命周期：检查保存、重算与跨图后的真实状态

适用：当次生成正确，重开、重算、重复标注或跨图复制后关联失效；测试只数实体而漏掉源修改。

操作要点：

- 从实际输入调用生产实现，按失效机制选择保存重开、关联读取、重算、重复命令或跨图复制；不为每个局部修复执行全部路径和组合。
- 源快照覆盖影响本次行为的几何、HATCH 环、完整类型化 XData 和关联。输出比较包括合同要求的有效样式及显示属性；句柄变化时核验关系映射，不要求跨库句柄字面相同。
- 比较器需理解宿主的合法序列化形式，例如某些空数组表示全直线。不得将真实字段差异当“格式差异”丢弃；识别比较器缺陷与生产缺陷的不同归属。
- 新增或修改关键保护/比较器时，用能区分真缺陷与合法变化的反例验证。确需故障注入时在隔离候选中进行，不污染发布产物；未改检查不为补报告重复注入。

复现：用目标生产链的相关案例检查修复结果与源数据保持。验证保护逻辑或比较器时，再用损坏字段或关联的反例确认真实读取器/断言能识别；不把故障注入列为所有生命周期修复的前置条件。不能仅证明测试用的替代算法正确。

案例 `01autocad-structure-detail`：`tests/Test-Lifecycle.ps1`、`Test-Local.ps1` 的 `Lifecycle` 入口，以及 `docs/1.0.2.29交付验证.md` 第 7 项、生命周期失败归属和故障注入记录。该版的增强源快照与冻结几何合同分开，不通过重写旧合同消除差异。

## 3. 首次克隆：验证实际语义，不等第二次才发现冲突

适用：首次导入貌似成功、重复导入才拒绝；缓存复用漏掉透明度、法向、镜像或尺寸平面变化。

操作要点：

- 在首次克隆前比较实际依赖的同名样式定义，克隆后回读目标语义；对象数量、名字或 ObjectId 相同不能代替定义一致。
- 普通命名资源按项目策略私有隔离；ByLayer、ByBlock、Continuous 等保留语义不能机械套普通记录重命名策略。本案例对实际不一致的保留线型采取首次拒绝并回滚，保留用户定义，不把这个选择推广为所有资源的统一策略。
- 签名覆盖消费者承诺保留的显示与几何字段。只要字段影响输出，就不能因当前样例没有差异而省略；签名与实际复制/回读字段保持一致。
- 特殊 API 返回值只在 SDK 及实测支持的窄条件解释，不能把任意读取失败归为“默认值”。

复现：按当前冲突类型选择干净目标、普通同名差异或保留线型差异，检查首次/重复导入。普通冲突验证自动隔离与正确输出；真正无法使用的依赖验证相应失败范围。受影响属性变化后不误用缓存、不覆盖用户定义。

案例 `01autocad-structure-detail`：`src/AnnotationNative.cpp` 的冲突隔离与原型签名；`docs/1.0.2.29交付验证.md` 第 5、8 项及首次导入红灯记录。普通自定义线型路径不能冒充本次真实保留线型故障样本。完整样式策略仍查[图纸兼容与交付一致性](drawing-compatibility.md)。

## 4. 目标诊断：区分看到了什么、缺什么、能采用什么

适用：多个图/楼层/类型共同提供输入，候选数量被误当完整覆盖，或读取器缺项被误报为原图缺项。

操作要点：

- 建立实际物理楼层、来源视图、构件/关系实例及输出用途的索引。共用来源不能抹掉不同物理层实例，框选最低层不能自动变成建筑首层。
- 明确区分未读取、未请求、读取缺项、冲突、多解、待逐层绑定及已有读取事实；没有独立来源证明时，不声称“原图没有”。单个候选不自动变成已解析身份。
- 先定位目标、物理层和真实依赖，再读取对应字段；不要求平面用途提供无关竖向字段，也不把平面轮廓当成完整竖向依据。
- 范围、字段、实际绘制和未完成部分分别报告。缺项只影响依赖它的部分；旧拒绝条件重新核对需求依据，不因已有合同就维持过宽门槛。

复现：在真实支持的目标输入中加入无关说明、额外轴线或其他视图，已有目标结果应保持；真正相关的冲突不能被忽略。按本次问题选取楼层、同名构件或共享来源变体。范围外的新组合另列能力，不将其变成当前修复的开发门槛。

案例 `00ifc-arx-dwg`：`stair_arx/include/StairTargetScope.h`、`StairPhysicalFloors.h`、`stair_arx/tests/StairTargetScopeTests.cpp`；规则见 `docs/STAIR_TARGET_SCOPE_CONTRACT.md`，历史证据见 `docs/validation/STAIR_TARGET_SCOPE_ALIGNMENT_2026-10-31/record.json` 及同目录 README。后续联动状态查当前阶段表，不把第一批的历史范围限制重新当成永久禁令。

## 5. 证据维护：从引用判断保留范围

适用：测试目录持续增长，需要识别哪些材料仍支撑当前版本、最后失败或故障复现。

按现有记录追踪“当前结果 → 报告/回执 → 运行目录/输入”。保留当前依赖及仍需定位的失败、关键对照；用途不明项先查明，不按目录名批量删除。自动保护集是保留下限，不是其余文件均可删除的证明，也不是永久累计所有历史的要求。

已有清理授权时按项目规则核实实际路径、依赖和替代结果，使用现有索引保留追溯；无需重复索要同一授权。移动与删除分别记录，不用清理消除当前失败。证据已移走时不能按原路径继续宣称可复用，也不为修复索引重跑未变化的 CAD 业务。

复现入口：`01autocad-structure-detail/tools/maintenance/Test-EvidenceReferences.ps1` 是现成只读检查器；其参数及保护范围以实际源码为准。案例判据与保留例外见 `docs/maintenance/2026-10-31-旧局部测试精简.md`，目录映射见同目录 `2026-10-31-旧局部测试移出索引.json`。旧运行移走后，原路径不能继续当完整可复用证据；恢复须核验原字节。

## 6. 报告身份校验的历史边界

2026-11-01 整理曾运行消费端测试，检查已有报告的协议、完成声明及文件身份。它只能证明“该报告是否对应这些文件”，不能证明 CAD 实际执行，也不能把没有本模块报告当成正常出图的禁止条件。

案例 `00ifc-arx-dwg`：`frontend/ifc_structure_worker/bridge.py::run_dwg_readback`、`frontend/tests/test_bridge_readback.py`、`docs/DWG_READBACK_IDENTITY_CONTRACT.md`。

历史6项用例通过只覆盖消费端，伪 DWG 字节不证明保存重开。真实运行证据按[验证参考](verification.md#core-console-完成证据与故障归属)判读；不要为使用本技能自动重跑案例项目。实时开发阶段由项目维护，技能不把旧“候选/暂缓”状态作为新任务停止点。

## 使用请求示例

- “使用 $autocad2020-objectarx，排查这条开放 PLINE 拆段后识别不同的问题，保留真实断口，并给出合法变体与坏数据反例。”
- “使用 $autocad2020-objectarx，复现首次导入样式冲突，检查保存重开及重复导入，说明源定义和失败回滚是否保持。”
- “使用 $autocad2020-objectarx，只读梳理这些缺项属于未读取、冲突还是尚未采用，列出真实来源及最小复现入口。”

这些请求调用当前技能的工作方法；案例项目、宿主、SDK 和业务输入仍需实际提供。没有附带独立测试执行器或一键通用出图能力。
